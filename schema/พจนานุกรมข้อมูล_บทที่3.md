# พจนานุกรมข้อมูล (Data Dictionary) — ฉบับแก้ไข
**ระบบจองคิวและจัดการให้บริการทำเล็บออนไลน์**

ฐานข้อมูลประกอบด้วย **10 ตาราง** ออกแบบตามหลัก Normalization (3NF)
Role ที่ล็อกอิน = 2 (admin, customer) · ช่างเป็น resource ในฐานข้อมูล ผู้ดูแลร้านเป็นผู้จัดการ

---

## ภาพรวมความสัมพันธ์
- หนึ่งลูกค้า (users) จองได้หลายครั้ง — หนึ่งการจองเป็นของลูกค้าคนเดียว (1:M)
- หนึ่งช่าง (staff) รับได้หลายคิว — หนึ่งคิวมีช่างคนเดียว (1:M)
- **หนึ่งการจอง (bookings) มีได้หลายบริการ** ผ่าน booking_items (M:N กับ services)
- หนึ่งช่างทำได้หลายบริการ / หนึ่งบริการทำได้หลายช่าง ผ่าน staff_service (M:N)
- หนึ่งช่างมีหลายช่วงเวลาทำงาน (staff_schedule) และหลายวันลา (shop_closure)
- หนึ่งการจองมีการแจ้งเตือนได้หลายครั้ง (1:M) และมีผลบริการ 1 รายการ (1:1)

## จุดที่แก้จากของเดิม (5 → 10 ตาราง)
1. **เพิ่ม staff** แยกจาก users — ช่างเป็น resource ไม่ใช่ role ล็อกอิน
2. **เพิ่ม staff_id ใน bookings** — แก้ปัญหา "ไม่มี FK ช่าง"
3. **เพิ่ม end_time ใน bookings** — ทำให้ตรวจคิวชนกันได้
4. **แยก booking_items (M:N)** — หนึ่งการจองมีได้หลายบริการ
5. **เพิ่ม price_snapshot / duration_snapshot** — รายงานรายได้ย้อนหลังไม่เพี้ยน
6. **เพิ่ม staff_service / staff_schedule / shop_closure** — รองรับอัลกอริทึมคำนวณ slot ว่าง
7. เปลี่ยน status เป็น ENUM, เพิ่ม created_at ทุกตารางหลัก

---

## อัลกอริทึมคำนวณช่วงเวลาว่าง (สำหรับเขียนในบท 3)
1. รวม `duration_min + buffer_min` ของทุกบริการที่เลือก → `required_minutes`
2. ดึงช่างที่ทำ**ครบทุกบริการ**ในชุดที่เลือก จาก `staff_service`
3. ดึงเวลาทำงานของช่างวันนั้นจาก `staff_schedule` (ตาม day_of_week) แล้วตัดวันปิด/วันลาจาก `shop_closure`
4. ดึงคิวที่จองแล้วของช่าง (`bookings` สถานะ pending/confirmed) → ได้ช่วงเวลาที่ถูกจอง
5. หาช่องว่างที่ยาว ≥ `required_minutes`
6. คืนค่าเป็น slot ทุก 30 นาที

## การป้องกันจองชนกัน (double booking)
เช็คตอนแสดง slot อย่างเดียวไม่พอ ต้องเช็คซ้ำระดับฐานข้อมูลตอน commit:
```sql
START TRANSACTION;
SELECT * FROM bookings
 WHERE staff_id = ? AND booking_date = ?
   AND status IN ('pending','confirmed')
   AND start_time < ?   -- end_time ของคิวใหม่
   AND end_time   > ?   -- start_time ของคิวใหม่
 FOR UPDATE;
-- ถ้าเจอแถว  -> ROLLBACK แล้วแจ้งลูกค้าว่าคิวเพิ่งถูกจอง
-- ถ้าไม่เจอ  -> INSERT booking + booking_items แล้ว COMMIT
```
